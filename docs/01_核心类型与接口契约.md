# 01_核心类型与接口契约

> 文档性质：Storage Core 核心类型、接口、不变量与错误语义的正式契约。  
> 适用阶段：V0～V2 为主要落地范围；V3～V11 仅预留稳定扩展点，不提前固化实现。  
> 目标：后续代码、测试、协议和 Benchmark 均以本文件为约束基础。

> 命名空间暂统一写为 `storage::`。项目正式命名后只统一替换一次，不改变本文语义边界。

---

## 1. 核心模型

Storage Core 长期围绕以下关系组织：

```text
Object
  ↓
Chunk
  ↓
Replica
  ↓
Worker
```

含义：

```text
Object
→ 用户看到的逻辑大对象

Chunk
→ Object 的连续切片

Replica
→ 某个 Chunk 在某个 Worker 上的一份物理副本

Worker
→ 提供数据读写和缓存能力的节点
```

长期保持以下架构约束：

1. Control Plane 不承载大对象数据流。
2. Data Plane 不负责 Placement 决策。
3. Client 根据 UploadPlan / ReadPlan 直接访问 Worker。
4. 业务管理平面不得直接依赖 Worker 内部实现。
5. Object 默认采用 immutable 语义。
6. 只有 READY Object 可以被普通 Get 读取。
7. 只有 READY Replica 才能进入新的 ReadPlan。
8. DEAD Worker 不得进入新的 Placement / ReadPlan。

## 3. 强类型 ID

### 3.1 ObjectId

```cpp
struct ObjectId {
    std::string value;
};
```

语义：Storage Core 中逻辑对象的唯一标识。

约束：

- `value` 不得为空；
- 不允许用空字符串表示“无对象”；
- 不直接承担业务 Artifact Version 语义；
- 必须支持相等比较；
- 如需用于 `unordered_map`，提供统一 Hash。

---

### 3.2 ChunkId

```cpp
struct ChunkId {
    std::string value;
};
```

语义：Object 内某个 Chunk 的唯一标识。

约束：

- 全局唯一，或至少在 Control Plane 生命周期内唯一；
- 调用方不得依赖字符串格式解析 Chunk 语义；
- ID 生成策略属于 Control Plane 实现细节。

---

### 3.3 ReplicaId

```cpp
struct ReplicaId {
    std::string value;
};
```

语义：某个 Chunk 的一份物理副本标识。

不变量：

- 一个 Replica 只属于一个 Chunk；
- 一个 Replica 在同一时刻只绑定一个 Worker；
- ReplicaId 不跨 Chunk 复用。

---

### 3.4 WorkerId

```cpp
struct WorkerId {
    std::string value;
};
```

语义：Worker 的稳定逻辑身份。

约束：

- 不直接等于 IP 地址；
- IP/Port 属于可变化的 Endpoint；
- 重连是否沿用 WorkerId 由注册协议决定。

## 4. 基础值类型

### 4.1 ByteRange

```cpp
struct ByteRange {
    std::uint64_t offset;
    std::uint64_t size;
};
```

语义：

```text
[offset, offset + size)
```

约束：

- 不允许 `offset + size` 溢出；
- Range Read 必须满足 `offset + size <= total_size`；
- 是否允许 `size == 0` 由具体接口定义。

建议提供：

```cpp
Status ValidateByteRange(
    const ByteRange& range,
    std::uint64_t total_size);
```

---

### 4.2 ChecksumAlgorithm

```cpp
enum class ChecksumAlgorithm {
    kBlake3,
};
```

V0～V2 仅支持 BLAKE3，但 Metadata 不把算法写死为裸字符串。

---

### 4.3 Checksum

```cpp
struct Checksum {
    ChecksumAlgorithm algorithm;
    std::string value;
};
```

语义：Object 或 Chunk 的内容摘要。

约束：

- 全项目使用统一编码；
- 空值不得表示“校验成功”；
- 编码方案一旦确定，各模块必须一致。

未来可替换为固定长度字节数组，但不影响语义。

## 5. ObjectState

```cpp
enum class ObjectState {
    kAllocating,
    kWriting,
    kReady,
    kFailed,
    kDeleting,
};
```

状态含义：

```text
kAllocating
→ 正在创建 Metadata / Placement

kWriting
→ Client 正在向目标 Replica 写数据

kReady
→ 完整提交，可以正常 Get

kFailed
→ 写入失败，不允许正常读取

kDeleting
→ 正在删除，不接受新的普通读写
```

核心状态转移：

```text
ALLOCATING
    ↓
WRITING
    ↓
READY
```

失败：

```text
ALLOCATING → FAILED
WRITING    → FAILED
```

删除：

```text
READY → DELETING
```

核心不变量：

> 只有 `kReady` Object 可以被 `GetReadPlan()` 正常返回。

## 6. ReplicaState

```cpp
enum class ReplicaState {
    kAllocating,
    kWriting,
    kReady,
    kFailed,
    kDeleting,
};
```

含义：

```text
kAllocating
→ 已有副本记录，尚未写入

kWriting
→ Worker 正在接收 Chunk

kReady
→ 数据完整且校验通过

kFailed
→ 写入或校验失败

kDeleting
→ 正在删除
```

核心不变量：

> 只有 `kReady` Replica 才允许进入新的 ReadPlan。

## 7. WorkerState

```cpp
enum class WorkerState {
    kHealthy,
    kSuspect,
    kDead,
};
```

语义：

```text
kHealthy
→ 可参与新的 Placement 和 ReadPlan

kSuspect
→ 心跳异常，不承担新的 Placement

kDead
→ 超过故障阈值，不进入新的 Placement / ReadPlan
```

规则：

- 一次请求失败不得直接永久判死；
- 状态由 Heartbeat / Timeout 驱动；
- V2 先实现基本 Healthy 流程；
- V5 完整实现 Suspect / Dead 自动迁移。

## 12. ChunkMetadata

```cpp
struct ChunkMetadata {
    ChunkId chunk_id;
    ObjectId object_id;

    std::uint32_t index;

    std::uint64_t offset;
    std::uint64_t size;

    Checksum checksum;

    std::vector<ReplicaMetadata> replicas;
};
```

字段语义：

```text
index
→ Chunk 逻辑序号

offset
→ 在 Object 中的起始位置

size
→ Chunk 字节数

checksum
→ Chunk 内容摘要
```

不变量：

```text
chunk.object_id == 所属 Object.object_id
```

连续 Chunk 必须满足：

```text
chunk[i].offset + chunk[i].size
==
chunk[i+1].offset
```

最后一个 Chunk 结束位置必须等于 Object.size。

V1 允许：

```text
Object = 1 Chunk
```

V2 开始真正支持多 Chunk。

## 13. ObjectMetadata

```cpp
struct ObjectMetadata {
    ObjectId object_id;

    std::uint64_t size;
    std::uint64_t generation;

    ObjectState state;

    Checksum checksum;

    std::vector<ChunkMetadata> chunks;

    std::chrono::system_clock::time_point created_at;
};
```

字段语义：

```text
size
→ 完整 Object 大小

generation
→ Metadata 版本，用于未来 ReadPlan Cache / stale detection

checksum
→ 完整 Object 摘要
```

核心不变量：

```text
Object.size == sum(chunks.size)
```

且：

```text
所有 chunk.object_id == object.object_id
```

READY Object 还必须满足：

- Chunk 布局完整；
- 每个 Chunk 存在合法读取来源；
- Object checksum 已确定；
- Commit 流程已完成。

## 14. UploadPlan 类型

### 14.1 ReplicaWriteTarget

```cpp
struct ReplicaWriteTarget {
    ReplicaId replica_id;
    WorkerId worker_id;
    WorkerEndpoint endpoint;
};
```

表示 Client 应把某个 Chunk 写到哪里。

不包含 socket、fd、连接对象。

---

### 14.2 ChunkUploadPlan

```cpp
struct ChunkUploadPlan {
    ChunkId chunk_id;

    std::uint32_t index;

    std::uint64_t offset;
    std::uint64_t size;

    std::vector<ReplicaWriteTarget> targets;
};
```

不变量：

```text
targets.size() >= 1
```

V2 初期可以：

```text
replica_count = 1
```

V4 再正式支持多副本。

---

### 14.3 UploadPlan

```cpp
struct UploadPlan {
    ObjectId object_id;

    std::string upload_id;

    std::uint64_t generation;

    std::vector<ChunkUploadPlan> chunks;
};
```

语义：Control Plane 对一次 Object 写入的完整规划。

规则：

- `upload_id` 唯一对应一次写事务；
- Client 不得自行增加 Plan 外 Worker；
- Commit 必须绑定对应 `upload_id`；
- 旧 generation 的 Plan 不得提交新对象状态。

### 15.1 ReplicaLocation

```cpp
struct ReplicaLocation {
    ReplicaId replica_id;
    WorkerId worker_id;
```


V2 不提前加入。

### 15.2 ChunkReadPlan

```cpp
struct ChunkReadPlan {
    ChunkId chunk_id;

    std::uint32_t index;

    std::uint64_t offset;
    std::uint64_t size;

    Checksum checksum;

    std::vector<ReplicaLocation> candidates;
};
```

规则：

- `candidates` 只包含 READY Replica；
- Candidate 所在 Worker 必须满足读取健康要求；
- Candidate 顺序允许表达优先级；
- Client 不得假定第一个 Candidate 永远成功。

后续可自然扩展：

```text
Read Fallback
Hedged Read
Locality Priority
Load-aware Ordering
```

### 15.3 ReadPlan

```cpp
struct ReadPlan {
    ObjectId object_id;

    std::uint64_t generation;
    std::uint64_t object_size;

    std::vector<ChunkReadPlan> chunks;
};
```

语义：Control Plane 对一次读取的定位结果。

不变量：

- Object 必须 READY；
- Chunk 完整覆盖 Object；
- generation 对应生成时 Metadata；
- Client 拿到 Plan 后直接访问 Data Plane；
- Control Plane 不参与数据搬运。

未来 ReadPlan Cache 使用：

```text
object_id + generation
```

判断是否过期。

# 17. MetadataStore

```cpp
class MetadataStore {
public:
    virtual ~MetadataStore() = default;

    virtual Status CreateObject(
        const ObjectMetadata& object) = 0;

    virtual StatusOr<ObjectMetadata> GetObject(
        const ObjectId& object_id) = 0;

    virtual Status UpdateObject(
        const ObjectMetadata& object) = 0;

    virtual Status DeleteObject(
        const ObjectId& object_id) = 0;
};
```

职责：

```text
保存和读取 Storage Core Object Metadata
```

不负责：

```text
Worker 心跳
Placement
Chunk Data
网络传输
```

### CreateObject

前置：

- ObjectId 合法；
- Object 尚不存在；
- Metadata 满足基本不变量。

主要错误：

```text
kAlreadyExists
kInvalidArgument
kIoError
kInternal
```

### GetObject

不存在：

```text
kNotFound
```

实现必须支持并发读取。

### UpdateObject

V2 采用：

```text
whole-object metadata replacement
```

逻辑更新必须原子，不允许外部看到半更新状态。

### DeleteObject

只表示删除 Metadata 记录。

它不等于所有 Replica 已经被物理删除。

## 18. WorkerRegistry

```cpp
class WorkerRegistry {
public:
    virtual ~WorkerRegistry() = default;

    virtual Status Register(
        const WorkerMetadata& worker) = 0;

    virtual Status Heartbeat(
        const WorkerId& worker_id,
        const WorkerCapacity& capacity) = 0;

    virtual StatusOr<WorkerMetadata> Get(
        const WorkerId& worker_id) const = 0;

    virtual std::vector<WorkerMetadata>
    ListHealthyWorkers() const = 0;

    virtual Status UpdateState(
        const WorkerId& worker_id,
        WorkerState state) = 0;
};
```

职责：

```text
Worker Membership
Endpoint
Capacity
Health
Heartbeat
```

不负责 Object Metadata 与 Chunk Data。

线程安全：

> Public 方法必须允许多个 Control Plane 请求线程并发调用。

### Register

V2 初期重复 WorkerId：

```text
→ kAlreadyExists
```

暂不提前设计复杂 Reconnect Session 语义。

### Heartbeat

前置：

```text
Worker 已注册
```

成功后更新：

```text
capacity
last_heartbeat
```

V2 可以简单保持：

```text
Heartbeat success → HEALTHY
```

## 19. PlacementPolicy

```cpp
class PlacementPolicy {
public:
    virtual ~PlacementPolicy() = default;

    virtual StatusOr<std::vector<WorkerId>>
    SelectWorkers(
        const PlacementRequest& request,
        const std::vector<WorkerMetadata>& workers) = 0;
};
```

职责：根据候选 Worker 为 Chunk 选择目标节点。

PlacementPolicy 禁止：

- 建立网络连接；
- 写 Chunk；
- 修改 Worker 本地数据；
- 直接访问业务层。

成功必须满足：

```text
返回 Worker 数量 == replica_count
WorkerId 唯一
Worker 来自候选集合
```

候选不足：

```text
kResourceExhausted / kUnavailable
```

版本演进：

```text
V2
SimplePlacementPolicy

V4
RendezvousPlacementPolicy
CapacityAwareRendezvousPlacementPolicy
```

## 26. StartPut 契约

主链：

```text
Validate
   ↓
检查 Object 是否存在
   ↓
切分 Chunk
   ↓
ListHealthyWorkers
   ↓
Placement
   ↓
创建 Object / Chunk / Replica Metadata
   ↓
Object → WRITING
   ↓
返回 UploadPlan
```

前置：

- ObjectId 合法；
- `object_size > 0`；
- checksum 合法；
- Worker 数量满足 Placement。

成功后：

- Object Metadata 已存在；
- Object 不能被普通 Get；
- UploadPlan 完整覆盖 Object；
- 每个 Chunk 至少有一个写目标。

V2 幂等语义：

```text
重复 ObjectId
→ kAlreadyExists
```

高层幂等以后由 UploadSession / Idempotency Key 实现。

---

## 27. CommitPut 契约

前置：

```text
object_id 存在
upload_id 匹配
generation 匹配
Object == WRITING
```

成功前必须确认：

- 必要 Chunk 已完成；
- 要求的 Replica 已 Ready；
- Checksum 验证完成。

成功：

```text
Object.state = READY
```

之后：

```text
GetReadPlan(object_id)
```

必须可以成功。

关键规则：

> 不能仅因为 Client 声称“写完了”就无条件把 Object 标成 READY。

## 28. GetReadPlan 契约

主链：

```text
    ↓

    ↓
ReadPlanBuilder::Build
    ↓
ReadPlan
```

错误：

```text
Object 不存在
→ kNotFound

Object 非 READY
→ kUnavailable

某 Chunk 无健康 Replica
→ kUnavailable

Metadata 不一致
→ kCorruption
```

## 32. 错误模型

统一：

```text
Status
StatusOr<T>
```

建议最低错误码：

```cpp
enum class StatusCode {
    kOk,
    kInvalidArgument,
    kNotFound,
    kAlreadyExists,
    kUnavailable,
    kTimeout,
    kIoError,
    kCorruption,
    kResourceExhausted,
    kInternal,
};
```

语义：

```text
kInvalidArgument
→ 调用参数非法

kNotFound
→ 请求目标不存在

kAlreadyExists
→ 创建目标已存在

kUnavailable
→ 对象存在，但当前暂时无法完成操作

kTimeout
→ 明确超时

kIoError
→ 文件 / socket / 系统 IO 错误

kCorruption
→ checksum 或 metadata invariant 破坏

kResourceExhausted
→ 容量、Worker、队列等资源不足

kInternal
→ 不应发生的内部错误
```

错误消息必须携带必要上下文：

```text
object_id
chunk_id
worker_id
operation
system error
```

但不得输出秘密凭据。

## 33. 线程安全

默认原则：

```text
Value Type
→ 不负责内部同步

Service / Store / Registry
→ 明确承担并发调用安全
```

V2 要求：

```text
MetadataStore
WorkerRegistry
ControlPlaneService
```

支持多个 RPC Handler 并发调用。

推荐：

```text
PlacementPolicy
ReadPlanBuilder
```

尽量 stateless。

`FileChunkStore` 至少支持：

```text
不同 Chunk 并发读写
```

同一个 Chunk 并发 Put 必须通过：

```text
AlreadyExists
或 per-chunk serialization
```

避免覆盖。

## 34. 生命周期与依赖注入

```cpp
class ControlPlaneServiceImpl final
```

# 43. 核心不变量汇总

## Object

```text
只有 READY Object 可以正常 Get
```

## Chunk

```text
Chunk 完整覆盖 Object
不得重叠
不得出现缺口
```

## Replica

```text
只有 READY Replica 可以进入 ReadPlan
```

## Worker

```text
DEAD Worker 不进入新的 Placement / ReadPlan
```

## UploadPlan

```text
完整覆盖 Object
每个 Chunk 至少有一个 Target
```

## ReadPlan

```text
完整覆盖 Object
所有 Candidate 满足当前读取条件
```

## Control Plane

```text
不搬运大对象 payload
```

## Data Plane

```text
不自行决定 Placement
```

## StorageClient

```text
协调 Control Plane 与 Data Plane
不得绕过 Control Plane 创建未登记 Replica
```
