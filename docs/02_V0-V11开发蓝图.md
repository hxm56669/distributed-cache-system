# 02_V0-V11开发蓝图

> 文档性质：项目从工程基线到最终可部署、可验证版本的阶段开发蓝图。  
> 依赖文档：
>
> - `项目总纲.md`
> - `AGENTS.md`
> - `01_核心类型与接口契约.md`
>
> 设计原则：
>
> - V0～V2：文件级、类级、函数级详细设计；
> - V3～V5：模块级 + 核心接口级设计；
> - V6～V11：边界级设计，不提前固化实现；
> - 每个阶段必须形成可运行闭环；
> - 每个阶段完成后先测试、验收、提交，再进入下一阶段；
> - 不允许跨阶段提前堆叠未来中间件。
>
> 命名空间暂使用：
>
> ```cpp
> namespace storage {
> }
> ```
>
> 项目正式命名后统一替换。

## 3.5 Status

建议接口：

```cpp
class Status {
public:
    Status();

    Status(
        StatusCode code,
        std::string message);

    static Status Ok();

    bool ok() const noexcept;

    StatusCode code() const noexcept;

    const std::string& message() const noexcept;

private:
    StatusCode code_;
    std::string message_;
};
```

最低 `StatusCode`：

```cpp
enum class StatusCode {
    kOk,
    kInvalidArgument,
    kNotFound,
    kAlreadyExists,
    kUnavailable,
    kTimeout,
    kIoError,
    kCorruption,
    kResourceExhausted,
    kInternal,
};
```

---

## 3.6 StatusOr<T>

目标：

```text
成功
→ 持有 T

失败
→ 持有 Status
```

要求：

- 禁止 `Ok Status + 无 value`；
- 禁止 `Error Status + value`；
- `value()` 只允许成功状态；
- 支持 move-only 类型。

## 6.1 FileChunkStore 路径规则

不要直接：

```text
root / chunk_id.value
```

如果 ChunkId 未来包含特殊字符会有风险。

V1 推荐：

```text
ChunkId
↓
固定编码
↓
文件名
```

例如：

```text
hex / base32 / stable safe encoding
```

必须：

- 禁止目录穿越；
- 禁止绝对路径；
- 禁止 `..`；
- ChunkStore 自己控制文件路径。

---

## 6.2 Put 语义

V1：

```text
不存在
→ 创建

已存在
→ kAlreadyExists
```

推荐写入流程：

```text
Create temp
    ↓
WriteAll
    ↓
Checksum
    ↓
fdatasync
    ↓
rename no-replace
```

即便 V1 暂不实现完整 crash-consistency，也不要直接裸覆盖最终文件。
